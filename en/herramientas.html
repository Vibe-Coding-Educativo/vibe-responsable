Tools and levels

Four families of tools

Not everyone works with the same means, and the tools for creating programs with artificial intelligence (AI) are very varied. Broadly speaking, they can be grouped into four families, presented below with some examples of those available in 2026.

  • A chatbot’s website. General assistants such as ChatGPT, Gemini or Claude, which create the application within the conversation itself. The material is hosted on the platform and shared through a link.
  • App-building platforms. Services such as Lovable, Bolt, Replit, Google AI Studio or Canva, which generate, host and publish the application from the browser.
  • Code editors with AI. Programs such as Visual Studio Code or Cursor, which are installed on the computer and include an assistant that writes and modifies the project files.
  • Coding agents. Programs such as Codex CLI, Antigravity (agy) or Claude Code, which receive instructions in natural language and work directly with the files on the computer.

The way of working

To follow this guide, what matters is the way of working that each tool allows. In the first two families the material lives on a company’s servers, and the company decides how long it is kept. On a chatbot’s website it is also a single piece. The code can usually be viewed, and even modified, but it cannot be accompanied by other files, such as the licence or the documentation, nor can changes be tracked conveniently. In the last two families the material is a folder of files on one’s own computer, which can be published on one’s own site or in a repository such as GitHub, where every change is recorded. The article «Consolas de IA: qué son y cómo se instalan» (in Spanish) explains how to start working with coding agents.

The minimum and the recommended

For this reason, each recommendation is set out in two levels of guidance. The minimum is what can be done with any tool, even when the material has been created and is shared within a chatbot’s website, and it is enough to publish responsibly. The recommended is what is also advisable, and it requires the material to be a project with its own files, published in a repository or on one’s own site. App-building platforms also tend to work with multi-file projects, and some allow them to be sent to an external repository, so in that case both levels can be followed. When there is no difference between one way of working and another, a single level is given.
